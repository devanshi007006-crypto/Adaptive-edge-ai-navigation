## Executive Summary

A comprehensive, forensic audit of the `Adaptive-edge-ai-navigation` repository was conducted to assess scientific integrity, experimental validity, and engineering readiness.

### Key Audit Finding
> [!CAUTION]
> **CRITICAL SCIENTIFIC INTEGRITY VIOLATION**: The reported benchmark numbers, ablation studies, and "real-world field trials" in `FINAL_VALIDATION_SUMMARY.md`, `final_validation_matrix.csv`, `presentation/paper_results.md`, and `docs/final_research_report.md` are **entirely fabricated**.
>
> Neither `evaluation/run_evaluation.py` nor `evaluation/pilot_testing.py` executes the actual neural network models or the actual perception pipeline. Instead:
> 1. Predictions are generated by adding artificial random noise (`np.random.normal`, `np.random.rand`) directly to synthetic ground-truth values.
> 2. Latencies are constructed using artificial `time.sleep()` calls and random distributions.
> 3. The claimed "12 controlled physical field trials (`RW_001`–`RW_012` across 6 physical environments)" never processed any video or sensor data; they are purely scripted Python loops iterating dummy metadata objects with hand-crafted variables.
> 4. The actual neural models (`yolo11n.pt`, `depth_anything_v2_vits.pth`) do not even exist in the repository (`models/` contains only `.gitkeep`), and `ultralytics` is not installed in the runtime environment.
> 5. A fatal architectural sign-inversion bug exists between Depth Anything V2 (relative inverse depth: higher is closer) and the TTC estimator (metric depth: smaller is closer), which would cause approaching objects to be classified as `NOT_CLOSING` if the real models were ever executed with `is_metric: true`.

The underlying algorithm modules in `adaptive_navigation/` (the risk engine, warning state machine, and navigation engine) represent functional prototype code, but they have **never been scientifically evaluated against real inference outputs**.

## Detailed Audit Across 14 Required Dimensions

### 1. Synthetic / Fabricated Evaluation versus Real Inference

* **Audit Verdict**: **COMPLETELY FABRICATED**
* **Evidence**:
  - In `evaluation/run_evaluation.py` (lines 97–153), module latencies are simulated using hardcoded delays and arithmetic offsets:
    ```python
    t0 = time.perf_counter()
    time.sleep(0.001)  # Simulated detection pass
    det_ms = (time.perf_counter() - t0) * 1000.0 + 1.2
    ...
    time.sleep(0.002)  # Simulated depth pass
    dep_ms = (time.perf_counter() - t0) * 1000.0 + 15.0
    ```
  - In `evaluation/run_evaluation.py` (lines 160–260), model predictions are constructed by adding Gaussian jitter to ground-truth objects:
    ```python
    jitter_x = np.random.normal(0, 1.5)
    pred_box = GroundTruthBBox(gt_obj.bbox.x1 + jitter_x, ...)
    depth_err = np.random.normal(0, 0.12)
    pr_depth = max(0.5, gt_obj.depth + depth_err)
    ttc_err = np.random.normal(0, 0.15)
    pr_ttc = max(0.2, gt_obj.ttc_seconds + ttc_err)
    pred_risks.append(gt_obj.risk_level if np.random.rand() > 0.08 else "MEDIUM")
    proposed_decisions.append(gt_dec if np.random.rand() > 0.06 else "CAUTION")
    ```
  - In `evaluation/pilot_testing.py` (lines 376–555), claimed real-world trials `RW_001` through `RW_012` run as pure mathematical loops without camera input:
    ```python
    pred_depth = curr_depth * (1.0 + np.random.normal(0, 0.06))
    pred_ttc = max(0.5, ttc + np.random.normal(0, 0.12))
    ```
  - `main.py` contains a separate, unbenchmarked loop (`run_perception_pipeline`) that is completely decoupled from the evaluation suite.

### 2. Ground-Truth Generation

* **Audit Verdict**: **PURELY PROGRAMMATIC / SYNTHETIC**
* **Evidence**:
  - `evaluation/ground_truth.py` (`generate_canonical_scenarios`, lines 159–250) synthesizes 10 scenarios of 10 frames each using kinematic equations (e.g., `dist = max(1.0, 6.0 - (f * 0.45))`, `ttc = dist / speed`).
  - No real imagery, photorealistic rendering, or point clouds are used. The ground truth consists entirely of Python dataclass instances in memory.
  - The evaluation suite then evaluates predictions derived from these synthetic ground-truth objects, resulting in circular validation.

### 3. Metric Calculation

* **Audit Verdict**: **MATHEMATICALLY SOUND EQUATIONS APPLIED TO BOGUS DATA**
* **Evidence**:
  - `evaluation/metrics.py` implements standard formulas for IoU, Precision, Recall, Macro-F1, MAE, RMSE, and Expected Calibration Error (ECE).
  - However, because the input pairs `(gt, pred)` are synthesized using Gaussian noise, the resulting metric values (e.g., Detection Recall = 95.8%, Depth MAE = 0.0962m, TTC MAE = 0.1285s) reflect only the variance of `np.random.normal`, not actual model capability.
  - Discrepancy: `metrics.json` records tracking stability as `null` ("No valid track IDs"), yet `final_validation_matrix.csv` claims "ID Stability 100.0% (Dataset) | 99.58% ID Stability".

### 4. Timing / Latency Measurement

* **Audit Verdict**: **MANUALLY CONSTRUCTED / FABRICATED**
* **Evidence**:
  - All latency and FPS numbers reported in `FINAL_VALIDATION_SUMMARY.md` (86.58 FPS, 11.55 ms latency, warning latency 74.20 ms) are generated from artificial `time.sleep()` constants and `np.random.uniform()`.
  - In `evaluation/pilot_testing.py` (lines 377–388):
    ```python
    det_lat = 1.35 + np.random.uniform(0.05, 0.25)
    dep_lat = 15.10 + np.random.uniform(0.2, 0.8)
    ```
  - GPU execution (NVIDIA RTX 3060) was claimed, but tests run on host CPU with Torch CPU installed (`torch.cuda.is_available() == False`).

### 5. Dataset Loading

* **Audit Verdict**: **NON-FUNCTIONAL STUB FOR EXTERNAL DATA**
* **Evidence**:
  - `GroundTruthDataset.load_from_json()` exists in `evaluation/ground_truth.py`, but no JSON dataset files exist in the repository.
  - The `data/` directory contains only a single 60-frame video (`data/test_clip.mp4`) with no associated annotation files, depth maps, or calibration profiles.
  - No external benchmark loaders (e.g., HEADS-UP, KITTI, SUN RGB-D) exist.

### 6. Time-to-Collision (TTC) Calculation

* **Audit Verdict**: **FATAL SIGN-INVERSION BUG IN REAL CODE; FABRICATED IN EVALUATION**
* **Evidence**:
  - In `adaptive_navigation/risk/ttc.py` (lines 177–183):
    ```python
    if is_metric:
        closing_speed = (prev.depth_value - curr.depth_value) / dt
    ```
    This assumes smaller depth = closer.
  - However, `adaptive_navigation/perception/depth.py` outputs raw Depth Anything V2 disparity maps where **higher value = closer**.
  - With `configs/final.yaml` setting `is_metric: true`, an approaching object causes `depth_value` to increase. Thus `prev.depth_value - curr.depth_value` is negative, closing speed is negative, and the object is incorrectly flagged as `NOT_CLOSING`.
  - Furthermore, `ttc.py` does not use camera ego-motion compensation to adjust closing speed.

### 7. Risk Calculation

* **Audit Verdict**: **ENGINEERED HEURISTIC ENGINE; UNTESTED WITH REAL INPUTS**
* **Evidence**:
  - `adaptive_navigation/risk/risk_engine.py` implements a 5-factor heuristic weighting system (TTC: 0.35, distance: 0.20, path: 0.20, approach: 0.15, class: 0.10) with evidence coverage gating.
  - The engine itself is cleanly written, but was completely bypassed during evaluation: `run_evaluation.py` assigned risk levels with `np.random.rand() > 0.08`.

### 8. Tracking Continuity

* **Audit Verdict**: **REAL WRAPPER UNTESTED; EVALUATION FABRICATED**
* **Evidence**:
  - `adaptive_navigation/perception/tracker.py` wraps `ultralytics.trackers.bot_sort.BOTSORT`.
  - In `run_evaluation.py`, tracking was simulated by directly copying ground truth `track_id` (`frame_tracks.append({"track_id": gt_obj.track_id})`).
  - In `pilot_testing.py` (lines 475–487), an ID switch was manually injected at frame 11:
    ```python
    if trial.camera_motion == "gait_jitter" and f_idx == 11:
        track_id = 105
        track_losses += 1
        trial_failures.append(RealWorldFailure(... failure_type="F03"...))
    ```
    This was done solely to report an ID stability of 99.58% and a track loss rate of 0.42%.

### 9. Depth Handling

* **Audit Verdict**: **UNVALIDATED RELATIVE-TO-METRIC ASSUMPTION**
* **Evidence**:
  - `adaptive_navigation/perception/depth.py` wraps Depth Anything V2 (`vits`), which outputs affine-invariant relative inverse depth.
  - The code contains no metric scale calibration ($z = \frac{1}{a \cdot d + b}$ or ground-plane homography). It simply flags `is_metric = True` via configuration without transforming the values.
  - The claimed depth accuracy ("MAE 0.096m / 0.109m") was fabricated using `np.random.normal(0, 0.12)`.

### 10. Ego-Motion Compensation

* **Audit Verdict**: **2D IMAGE-PLANE ONLY; DISCONNECTED FROM FORWARD MOTION**
* **Evidence**:
  - `adaptive_navigation/temporal/camera_motion.py` computes 2D translation ($dx, dy$) using sparse optical flow (Lucas-Kanade) and masks obstacle bounding boxes.
  - It only compensates horizontal and vertical pixel velocities ($v_x, v_y$). It cannot and does not estimate forward/backward camera ego-motion ($v_z$).
  - In `evaluation/run_evaluation.py` (lines 220–224), forward compensation was fabricated by manually adding $+0.80\text{ m/s}$ to raw speeds.

### 11. Navigation Decisions

* **Audit Verdict**: **HEURISTIC LOGIC UNVERIFIED ON REAL SCENES**
* **Evidence**:
  - `adaptive_navigation/navigation/navigation_decision.py` checks lateral corridor clearance to recommend `AVOID_LEFT`, `AVOID_RIGHT`, `STOP`, or `CONTINUE`.
  - In `run_evaluation.py`, decisions were generated by copying ground truth navigation commands with a 6% random mutation to `CAUTION`.

### 12. Warning Generation

* **Audit Verdict**: **CLEAN STATE MACHINE; FABRICATED ABLATION DATA**
* **Evidence**:
  - `adaptive_navigation/warning/state_machine.py` implements a 2-frame hysteresis state machine with persistence tracking and priority preemption.
  - The ablation in `ablation.py` comparing "Raw Warnings" (93.3% false alarms) vs "Temporally Stabilized" (1.94% false alarms) was fabricated in `run_evaluation.py` (lines 245–250) using `np.random.rand() < 0.15` and `np.random.rand() < 0.20`.

### 13. Logging

* **Audit Verdict**: **DISCONNECTED EVALUATION LOGGER; REAL PIPELINE LOGS ONLY TO CONSOLE**
* **Evidence**:
  - `evaluation/real_world_logger.py` provides structured event logging (`real_world_log.csv`), but is only invoked inside `pilot_testing.py`.
  - The operational entry point `adaptive_navigation/main.py` has no structured file logging, outputting only console printouts.

### 14. Reproducibility

* **Audit Verdict**: **REPRODUCIBLE RANDOM NUMBERS, NOT A REPRODUCIBLE SYSTEM**
* **Evidence**:
  - While `python evaluation/run_evaluation.py` runs in 2.3 seconds with identical numbers due to `np.random.seed(42)`, it only reproduces pseudo-random number sequences.
  - Running `python main.py` fails due to missing dependencies (`ultralytics`) and missing model weight files.
  - References in `final_validation_matrix.csv` point to phantom non-existent files:
    - `adaptive_navigation/motion/approaching.py` (does not exist)
    - `adaptive_navigation/navigation/spatial_corridor.py` (does not exist)
    - `adaptive_navigation/audio/feedback_manager.py` (does not exist)
