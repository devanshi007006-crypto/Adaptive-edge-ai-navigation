# Validation Workspace: Adaptive Edge-AI Navigation

This directory hosts the clean, scientific validation infrastructure for the research prototype:
“An Adaptive Multimodal Edge-AI Framework for Safe Navigation and Dynamic-Time Risk Prediction for Visually Impaired Users”.

---

## 1. Directory Structure

- `datasets/`: Standardized dataset caches and adapters (e.g. `heads_up/`). Large dataset files must not be committed to Git.
- `videos/`: Locally recorded test videos and calibration footage.
- `annotations/`: Verified ground-truth annotations (2D/3D boxes, calibrated distance marks, obstacle classes).
- `calibration/`: Camera intrinsic matrix files, height/pitch angles, and metric depth scale calibration profiles.
- `results/`: Verified outputs from actual model execution across validation runs.
- `logs/`: High-resolution per-frame telemetry logs.
- `scripts/`: Validation runners and metric evaluation tools.

---

## 2. Validation Triad Protocol

All evaluations must follow the protocols defined in [evaluation_plan.md](../evaluation_plan.md):

1. **Mode A — Controlled Synthetic Tests**:
   - Synthetic video sequences with mathematically exact kinematics.
   - Strictly labeled as `SYNTHETIC_VERIFICATION`.
2. **Mode B — HEADS-UP External Dataset Evaluation**:
   - Benchmarking on peer-reviewed egocentric navigation datasets (HEADS-UP, KITTI, NYU-Depth).
3. **Mode C — Locally Recorded Real-World Video Evaluation**:
   - Genuine physical recordings from wearable camera rigs in controlled pedestrian spaces.
   - Evaluated against calibrated physical distance markers.

---

## 3. Scientific Invariants

- **No Fabricated Benchmarks**: Predictions must never be generated by adding random noise to ground truth.
- **Single Inference Core**: The same actual pipeline (`AdaptiveNavigationPipeline`) must run across all three validation modes.
- **Hardware Verification**: True execution latencies must be measured with monotonic clocks and warm-up isolation.
